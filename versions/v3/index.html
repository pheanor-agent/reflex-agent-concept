01 From concept to contract

구상이 실행 계약이 되었다

v2는 “익숙한 일은 짧게 처리하는 에이전트”를 그렸습니다. v3는 그 그림의 각 칸을 코드가 집행하는 계약으로 바꿨습니다. 아래 버튼으로 같은 항목을 구상과 구현으로 번갈아 보세요.

02 The host decides

모델은 제안하고, 호스트가 판정한다

빠른 경로를 믿으려면 먼저 느린 경로가 정직해야 합니다. Reflex는 모델의 말을 성공의 증거로 쓰지 않습니다. 키와 예산, 효과 기록, 정지, 결과 판정은 모델 바깥의 호스트(controller)가 소유합니다.

그래서 v3의 첫 원칙은 “더 똑똑하게”가 아니라 “검증할 수 있게”입니다. 모델의 완료 문구는 기록상 unverified로 남고, 성공은 호스트의 독립 판정과 체크포인트가 정합니다.

03 One request, eight gates

요청 하나는 여덟 개의 관문을 지난다

스크롤을 내리면 “아까 작업 이어서 마무리해줘”라는 한 문장이 결과가 되고, 다시 다음 판단을 위한 경험이 되는 과정을 따라갑니다.

GATE 01 · 대화

말로 시작한다

사용자는 plan JSON이나 Run ID를 만들지 않습니다. “진행 상황 알려줘”, “이 작업 그만해”, “아까 작업 이어서 마무리해줘”처럼 말하면, 대화는 세션 원장에 먼저 기록되고 작업 lane과 별도의 상태·중단 입구로 나뉩니다.

ChatService · SessionRepository

GATE 02 · 고정

시작 전에 모든 조건을 못 박는다

의도를 해석하기 전에 입력, 지식 범위, 권한, 예산, 모델, 코드, 학습된 구조 묶음 전체를 하나의 admission으로 고정합니다. 실행 도중 정책이 슬쩍 바뀌는 일은 없습니다.

admission · bundle pin

GATE 03 · 의도 계약

의도는 계약의 형태로만 말한다

모델은 자유 문장이 아니라 정해진 intent 스키마로 답합니다. 원 요청에 들어 있던 읽기·쓰기·실행 의무(파일 좌표, 실행할 시험, 출력 위치)가 데이터로 끝까지 전달되고, 빠진 의무는 한 곳에서 판정됩니다.

intent_contract · completion/2

GATE 04 · 계층 선택

판단마다 맞는 계층을 고른다

적격성 검사를 통과한 경로만 후보가 됩니다. 낯선 일은 격리된 L3 에이전트에게, 익숙한 해석은 L2 모델에게, 닫힌 선택은 L1 표에게, 검토를 마친 절차는 L0 코드에게 갑니다. 어느 쪽이든 같은 실행기와 같은 효과 통로를 씁니다.

route · select · Decision

GATE 05 · 격리 실행

작업 하나에 방 하나

네이티브 실행은 Run마다 새 bubblewrap 방에서 돌아갑니다. 쓸 수 있는 곳은 그 Run의 /work뿐이고, 외부 네트워크는 막혀 있으며, 진짜 API 키 대신 그 Run 전용 capability만 받습니다. 모든 모델 호출은 보내기 전에 예산에서 먼저 차감됩니다.

native sandbox · attempt reservation

GATE 06 · 독립 검증

결과는 만든 쪽이 아닌 쪽이 판정한다

파일 존재·내용·SHA-256 같은 관측 가능한 조건, 그리고 원 요청의 시험이 실제로 실행됐다는 영수증으로 판정합니다. 실패하거나 효과가 불확실하면 성공으로 추정하지 않고 멈춰 둡니다.

host acceptance · completion receipt

GATE 07 · 체크포인트

검증된 단계만 체크포인트가 된다

단계마다 파일 해시와 계약 지문이 남습니다. 프로세스가 죽어도 다시 열 때 이전 체크포인트를 전부 재확인하고, 누락·변조·계약 변화가 보이면 자동 재실행 대신 검토 상태로 둡니다.

Goal checkpoint · needs_review

GATE 08 · 경험

끝난 일은 다음 판단의 재료가 된다

완료된 Goal은 독립 판정·출처·비용이 붙은 에피소드가 됩니다. 학습용·선택용·봉인 평가용으로 나뉘어 저장되고, 여기서 다음 요청을 더 짧게 처리할 후보가 자랍니다.

episode · train / selection / sealed

04 Bounded by construction

경계는 약속이 아니라 구조다

격리가 없으면 실행을 거절합니다. 격리되지 않은 대체 경로는 없습니다. 오른쪽 방 안의 에이전트에게 직접 시도를 시켜 보세요.

Goal 시도 예산24 / 24

예산 24회는 설치 안내의 예시 값입니다. 차감은 전송 전에 SQLite에서 원자적으로 일어나며, 오류·취소·늦은 응답도 환불하지 않습니다.

끊겨도 처음부터 다시 하지 않는다

긴 일은 언젠가 끊깁니다. Reflex의 Goal은 원 요청과 단계, 예산, 만료 시각을 SQLite에 들고 있습니다. 아래 애니메이션은 세 번째 단계에서 프로세스가 죽은 뒤, 새 프로세스가 체크포인트를 재확인하고 남은 단계만 이어가는 과정입니다.

“그만해”는 다음 시작까지 막는다

명시적 정지는 Goal에 걸려 남고, 이어가기 요청이 몰래 풀지 않습니다.

unknown effect

모르면 성공이라 하지 않는다

중간에 끊겨 효과가 불확실한 Run은 관측된 파일·영수증과 대조해 따로 정리합니다. 원 Run은 고치지 않습니다.

installed check

설치본에서도 같은 동작

b14 설치본의 오프라인 Goal은 1/2단계 뒤 일시정지, 이어가기 뒤 두 단계 검증과 성공으로 끝났습니다.

06 Eleven judgments, four depths

작업 전체가 아니라 판단마다 계층이 내려간다

v2는 “작업마다 계층을 고른다”고 했습니다. v3는 한 작업을 열한 개의 의미 단위로 쪼개고, 단위마다 따로 경험을 쌓습니다. 해석은 여전히 L3에 남아 있어도, 해시 검증은 일찌감치 L0로 내려갈 수 있습니다.

0 · 처음 보는 일

위 행렬은 개념 시뮬레이션입니다. 실제 하강 순서와 시점은 단위별 독립 평가가 정합니다. 단위 이름은 코드의 operation 목록 그대로입니다.

실측 · 통계 업무

새 입력을 모델 호출 0회로

통계 절차를 검증된 실행 경험과 연결한 뒤, 학습에 쓰지 않은 새 입력을 고성능·저비용 두 모델 설정 모두에서 L0, 모델 0회·워커 0회, 236.6 ms / 233.2 ms로 처리했고 답도 맞았습니다.

단, 호스트가 미리 작성한 통계 절차를 연결한 결과이며 임의 코드를 새로 배운 것은 아닙니다.

원칙

숙련은 권한을 늘리지 않는다

단위가 L0로 내려가도 쓸 수 있는 파일, 부를 수 있는 도구, 쓸 수 있는 예산은 그대로입니다. 비용 선택은 현재 권한 상한을 낮추지 않습니다.

07 Promote slowly, roll back at once

승격은 느리게, 복귀는 한 번에

짧은 경로가 활성화되려면 여러 겹의 문을 지나야 합니다. 서로 다른 입력에서 나온 깨끗한 성공 사례 둘, 알려진 효과, 고정된 검증, 독립 평가가 모두 있어야 후보가 되고, 봉인된 평가를 통과한 묶음만 명시적으로 채택됩니다. 문제가 생기면 묶음 전체가 이전 버전으로 돌아갑니다.

source-backed

교훈에는 출처가 붙는다

일반 교훈 후보는 실제 근거 파일의 위치·해시와 함께 남고, 채택·소비·복귀가 원장에 이어집니다.

pair

실행과 검증은 짝으로 움직인다

실행 후보와 검증 후보를 각각 활성화하는 우회는 없습니다. 같은 트랜잭션에서 짝을 짓고 봉인 평가 뒤에만 채택합니다.

pin

진행 중인 일은 버전이 고정된다

새 묶음은 새 admission부터 적용됩니다. 이미 시작된 작업의 구조는 바뀌지 않습니다.

08 Watching before predicting

다음 판단을 위한 예측은 아직 그림자 속에서 배운다

가장 최근 개선은 “이 일을 어느 경로로 보내면 성공할까”를 미리 가늠하는 관측 장치입니다. 다만 아직 경로를 바꾸지 않습니다. 충분히 맞는다는 독립 근거가 쌓일 때까지 기록만 합니다.

shadow predictor

판단 전 정보만 쓴다

역할·업무 계약·입력 형식처럼 결정 이전에 알 수 있는 특징만 씁니다. 사례 5개 미만은 “부족”, 그 이상도 보정 근거가 없으면 “신뢰 불가”로 표시합니다.

context manifest

모델이 본 것을 남긴다

호출마다 프롬프트·도구의 지문, 근거 범위, 잘림 여부, 추정 토큰을 기록합니다. 원문은 복제하지 않습니다.

episode search

성공과 반례를 나눠 찾는다

최근 5,000건 안에서 성공·반례·미분류를 범주별 최대 20건씩 돌려줍니다. 출처가 없으면 단순 관측으로만 취급합니다.

sealed receipt

채택 직전에 다시 대조한다

짝 평가와 묶음 전체 평가가 PASS·FAIL·부족·미실행으로 따로 표시되고, 실제 봉인 영수증과 맞을 때만 채택됩니다.

10 Where it actually stands

숫자는 아직 겸손하고, 그래서 믿을 만하다

b13 설치본을 실제 모델과 바닐라 Hermes 대조군으로 처음 돌린 32개 배정의 결과입니다. 실패는 덮어쓰지 않고 그대로 남겼습니다. 이 기록이 b14의 설계 근거가 되었습니다.

확인한 것

  • 격리 실행, 선차감 예산, 정지·만료가 설치본에서 동작한다
  • 재시작 뒤 체크포인트를 재확인하고 남은 단계만 이어간다
  • 학습된 후보가 실제로 고정·소비되고 복귀할 수 있다
  • 제한된 통계 업무에서 새 입력을 모델 호출 없이 처리했다

아직 증명하지 못한 것

  • 일반·후속 업무 24개 중 통과는 3개다
  • 세 비교군이 모두 통과한 학습 짝은 0/8, 비용 감소도 관측되지 않았다
  • 코드 작업 4건이 실행 전 거절되었다 (b14에서 원인 보완, 재시험 전)
  • b14의 실제 업무 비교와 운영 Hermes 대체는 아직 실행 전이다

REFLEX는 “벌써 된다”고 말하지 않습니다. 대신 무엇이 실패했는지 정확히 아는 상태에서 다음 버전을 만듭니다. 빠른 경로를 믿을 수 있게 하는 것은 결국 이 기록입니다.
